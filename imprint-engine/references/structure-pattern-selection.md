# Structure Pattern Selection: Strict Six-Layer vs Path C

This file is the execution manual for Stage 0 in `SKILL.md`. **Before generating any documents, you must first select the structure pattern for the role profile** — the wrong structure pattern will cause all subsequent work to be built on a skewed foundation.

---

## Why Structure Pattern Matters

The structure pattern determines the hierarchical skeleton of `01-岗位职责定义.md`, and `02/03/04` all follow this skeleton. It also determines the profile's "narrative voice" — whether it's a single-discipline "vertical depth narrative" or a composite-discipline "lateral combat narrative."

Typical symptoms of choosing the wrong structure:
- Forcing Path C onto a single discipline (e.g., frontend engineer) → the profile becomes flat and loose, losing professional depth
- Using strict six-layer for a composite discipline (e.g., growth expert) → the profile is forced into a single narrative line, losing combat dimension differentiation

---

## Two Structure Patterns

### Pattern 1: Strict Six-Layer

**Applicable to**: **Single disciplines** — roles whose core activities are concentrated within one clearly defined professional domain.

**Typical applicable roles**:
- Product Expert / Product Manager
- Frontend / Backend / Full-Stack Engineer
- UX Designer / Visual Designer
- User Researcher
- Data Scientist / Data Analyst
- Finance / Legal / HR and other functional specialists

**Six-layer structure**:

```
I.   Strategy Layer
     Focus on "why we do it, where we're heading" — vision, goals, long-term direction
II.  Tactics Layer
     Focus on "how to plan, how to prioritize, how to make trade-offs" — paths, priorities, opportunity assessment
III. Execution Layer
     Focus on "how to get things done, how to ensure quality" — output, delivery, quality
IV.  Craft Depth Layer
     Focus on "what makes this discipline's craftsmanship unique" — professional judgment, craft mastery, aesthetic taste
V.   Organization Layer
     Focus on "how to collaborate, how to empower, how to build systems" — influence, mentoring, mechanisms
VI.  Self-Evolution Layer
     Focus on "how to keep growing, how to pave the way for the next generation" — learning, reflection, legacy
```

**Narrative characteristics of the six layers**: From "why" to "how," then from "personal craft" to "organizational impact," and finally to "self-evolution" — forming a **vertical depth** narrative. Each layer is "ascending one dimension" from the previous layer.

**Strengths**:
- Stable and reusable structure — any single discipline can adopt it
- Clear hierarchy, easy for the Agent to build a "self-awareness pyramid"
- Easy to track gaps and orphans during cross-validation

**Weaknesses**:
- Feels "forced" for composite disciplines — the activity scope is too broad for a single dimension to contain

---

### Pattern 2: Path C (Core Spine + Combat Dimensions)

**Applicable to**: **Composite disciplines** — roles that span multiple professional domains and require multiple combat capabilities simultaneously.

**Typical applicable roles**:
- Growth Expert (spanning strategy + data + acquisition + content + product)
- Operations Expert (spanning content + events + data + users + channels)
- Monetization Expert (spanning pricing + channels + product + data)
- Product Operations (spanning product + operations + data)
- Chief of Staff (spanning strategy + organization + projects + communication)

**Path C structure**:

```
I.   Core Spine
     The "combat thesis" of this composite discipline — all combat dimensions revolve around it
     Example (Growth Expert): Building and amplifying a "sustainable user value growth engine"
     Example (Operations Expert): "Systematic management of user lifecycle value"

II.  Combat Dimension 1
III. Combat Dimension 2
IV.  Combat Dimension 3
V.   Combat Dimension 4
     The 4 combat dimensions typically correspond to the 4 major activity domains of the discipline
     Example (Growth Expert): Strategy & Experimentation / Market & Acquisition / Content & Narrative / Product-Led & Retention

VI.  Cross-Dimensional Responsibilities
     Overarching, cultural, and organizational cross-cutting responsibilities
     Example: Building growth culture, cross-functional collaboration, retrospective mechanisms, team building
```

**Narrative characteristics of Path C**: With one **core spine** as the backbone, 4 **combat dimensions** extend outward like limbs — forming a "spine + four-dimensional expansion" **lateral combat** narrative.

**Key difference**: Path C is not a "strategy to execution" vertical narrative, but a "fighting in parallel across multiple combat dimensions" lateral narrative. A composite discipline expert doesn't "go deep in one layer" but rather "can independently operate and coordinate across multiple dimensions."

**Strengths**:
- Can accommodate the multi-dimensional activity scope of composite disciplines
- Combat dimensions are parallel, avoiding forced vertical layering
- The core spine ensures the profile doesn't lose coherence

**Weaknesses**:
- Higher requirements for structural design — the spine and dimensions need careful thought
- Beginners tend to write "four independent sub-disciplines," losing holistic integrity

---

## How to Determine Which Pattern a Role Belongs To

**Criterion 1: Width of the activity scope**
- Single discipline: Core activities concentrated in 1-2 professional domains
- Composite discipline: Core activities distributed across 3+ parallel professional domains

**Criterion 2: JD profiles in the hiring market**
- Review 5-10 JDs from leading companies for this role, examine the responsibility descriptions
- If JDs consistently revolve around a single keyword (e.g., "product design," "backend architecture") → Strict Six-Layer
- If JDs feature "simultaneously possessing A + B + C + D capabilities," "must do X... and Y... and also Z..." → Path C

**Criterion 3: Classic course systems in the industry**
- The discipline has a single vertical professional course system (e.g., UX design courses) → Strict Six-Layer
- The discipline requires assembling multiple course modules (e.g., Reforge's growth curriculum consists of Acquisition, Retention, Monetization, Experimentation, and other separate courses) → Path C

**Criterion 4: The "combat picture" of daily work**
- The expert's day is "deep-diving into one problem, pursuing craft excellence" → Strict Six-Layer
- The expert's day is "switching between multiple fronts, coordinating multiple dimensions" → Path C

## "De-Management" Treatment for Path C

This is where Path C is most prone to errors and **must be specifically addressed**.

### What "De-Management" Means

Many composite disciplines (growth, operations, monetization) typically have teams at leading companies, so traditional JDs tend to be written in a "growth lead managing a growth team doing XXX" managerial tone. But Imprint Engine's Agent profiles must **emphasize "combat capability" rather than "managerial identity."**

**Rationale**:
1. An Agent is a digital employee — it has no "direct reports" to manage
2. Staff/Principal-level individual contributors (ICs) are precisely the composite of "can independently operate + can build and scale teams," not pure managers
3. Prematurely defining a role as "manager" reduces the profile's actionability

### Three Rules for De-Management

**Rule 1: Use verbs like "operate/design/build/deconstruct," avoid "manage/oversee/coordinate"**
- ❌ "Manage the growth team's daily operations"
- ✅ "Independently operate the complete growth engine from acquisition to retention"

**Rule 2: Use identity framing of "combat operator + team builder," avoid "lead/head/manager"**
- ❌ "As the growth lead, lead the team to achieve quarterly growth targets"
- ✅ "Can personally write ad copy and run experiments, and can also build a 3-5 person combat squad during the scaling phase"

**Rule 3: Write Organization Layer responsibilities as "system building and empowerment" rather than "management and reporting"**
- ❌ "Report growth progress to the CEO, manage team OKRs"
- ✅ "Establish a growth operational cadence (weekly experiment reviews, monthly retrospectives, quarterly campaigns), codify methodologies into team-inheritable playbooks"

## Special Cases and Hybrid Patterns

**Case 1: Roles that start as single discipline but become composite later**
For example, "early-stage operations" is a single discipline, while "mature-stage operations lead" is a composite discipline. Choose based on the **target level** — since Imprint Engine only creates Staff/Principal-level profiles, select the structure based on the mature form.

**Case 2: Roles with ambiguous boundaries**
For example, "product operations" can lean toward product (single) or operations (composite), depending on the company. Clarify the role's emphasis with the user during Stage 0 interviews, then decide the structure.

**Case 3: Path C is needed but the number of dimensions ≠ 4**
Some composite disciplines have only 3 combat dimensions (e.g., certain "triangular combat" roles) or 5 dimensions. **4 is the recommended number but not mandatory** — the core is the "one spine + parallel dimensions + cross-dimensional responsibilities" skeleton.
